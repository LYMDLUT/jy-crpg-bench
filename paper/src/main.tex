\begin{abstract}
Long-horizon agency requires an agent to perceive an unfamiliar world, decide
without being told what is worth doing, and stay coherent over hundreds of
dependent decisions. We introduce \bench{}, a benchmark that places a
vision-language agent inside \game{金庸群俠傳} (\emph{Heroes of Jin Yong},
Heluo Studio 1996), an unmodified commercial open-world role-playing game run
under DOS emulation, and measures it against the ending the game itself
defines: recovering the fourteen books of the Jin Yong canon, which a
first-time human player reaches in tens of hours. The environment is far from
the distribution modern vision encoders are trained on, with a
$320\times200$ framebuffer, a $45^\circ$ isometric projection in which no key
moves straight up the screen, Traditional Chinese rendered as 16-pixel bitmap
glyphs, and objectives stated only in its own fiction. An agent joins by
pointing an HTTP client at a session URL, so any model under any harness can
play without adopting a framework. We score from the state of the emulated
machine and from the save file the game writes for itself, so the party, the
character records, the inventory and the books are read as the game stores
them and cannot be reached by pixel similarity. One instrument spans the whole
distance: a milestone ladder while agents are learning to move, and completion
time once they can finish, which keeps ordering the field after the first
model arrives. We report the standing of \NmodelLabels{} agent configurations
from \Nvendors{} vendors against a seeded random baseline: the field clears
the opening rungs, the character-progression rungs above them are still open,
and the behavioural profile separates configurations that share a progression
result. We release
\bench{} as a live, replayable public arena at
\url{https://github.com/hanxiao/jy-crpg-bench}.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Frontier models prove competition mathematics and write working compilers,
yet remain unreliable on tasks that unfold over hours.
Surveys of this gap converge on a single diagnosis: outcome-only signals
become uninformative as horizons lengthen, so evaluation has to manufacture
denser step-level evidence to say anything at all \citep{chen2026horizongap}.
Long-horizon benchmarks answer this in two families. Episodic benchmarks set
a goal and score its completion. Continuing benchmarks give the agent an
environment with no terminal state and score what accumulates
\citep{backlund2025vending,fan2026ecommerce}. Open-world games belong to the
second family and add a requirement the business simulations do not: the
agent must recover its own state from raw perception, because nothing in the
environment reports it.

Existing game benchmarks each remove one part of that problem to isolate
another. BALROG evaluates six research environments in language-only and
language-vision modes \citep{paglieri2025balrog}; TextQuests removes
perception entirely \citep{phan2025textquests}; ARC-AGI-3 excludes language
and cultural priors by construction \citep{arc2026arcagi3}; VideoGameBench
detects progress in real-time action games by matching against checkpoint
images taken from walkthroughs \citep{zhang2025videogamebench}; MineExplorer
filters out tasks whose solutions depend on game-specific knowledge
\citep{ju2026mineexplorer}. Each removal is principled, and each leaves the
combination untested. We keep the parts together, because acting through
unfamiliar perception, unfamiliar language and unfamiliar culture at once is
what a deployed agent is asked to do.

\bench{} runs one deep environment in place of a wide suite, following the
precedent set by Crafter and NetHack
\citep{hafner2021benchmarking,kuttler2020nethack}. The environment is
\game{金庸群俠傳}, a 1996 Chinese role-playing game that remains a landmark
of its genre, executed as its original DOS binary under emulation with no
modification. The game presents an open world built from the fourteen novels
of Jin Yong: a two-tier map, several hundred named characters each carrying
level, experience, skills, items and reputation, and a completion condition
that requires recovering fourteen books scattered across the world. A first
human playthrough takes tens of hours. The agent receives the framebuffer and
a key vocabulary, and nothing else.

We measure against that ending. The fourteen books sit behind items,
factions and martial arts that have to be
acquired in order, in a world that reports nothing about itself, and the game
records whether they have been recovered. An agent that finished would have
held one plan across tens of hours of self-directed play, which is the
capability long-horizon evaluation exists to detect. We therefore built the
instrument for the whole distance. A ladder of machine-verified milestones
orders the field while agents are learning to move through the world, and
completion time orders it once they can finish, so the benchmark gains a
speedrun ranking at the point where a pass-or-fail score would saturate.

Three properties make the environment adversarial for current models in ways
a modern title would not be, and \cref{fig:opening} shows the world they apply
to. Perception is out of
distribution on several axes at once: native-resolution studies report that
the usual downsampling path costs vision-language models accuracy
\citep{niu2025resolution}, corruption studies measure systematic sensitivity
to degraded input \citep{wasim2025corruptions}, out-of-distribution image
benchmarks find degradation even on familiar categories
\citep{lin2026oodbench}, and text rendered as pixels is understood less well
than the same content supplied as text \citep{liu2026vistabench}. A
$320\times200$ frame of 1996 bitmap art with 16-pixel Traditional Chinese
glyphs sits at the hard end of all four. Control is projected: the world is drawn
in a $45^\circ$ isometric projection, so the four movement keys run along
screen diagonals and an agent reasoning in screen
coordinates walks in circles. Progress is self-directed: the game keeps no
quest log, draws no objective marker, and reports no score, so deciding that
the chest is worth searching and that the compass gates the rest of the world
is the problem the agent has to solve. ARC-AGI-3 places the same
goal-setting requirement at the centre of agency \citep{arc2026arcagi3}.

Measuring such an environment from the screen is unreliable, and the field
has begun to say so: GameWorld names heuristic verification as the obstacle to
standardized game-agent evaluation and pairs each of its tasks with a
state-verifiable metric \citep{ouyang2026gameworld}. We take the same
position and push it into the emulator. The benchmark reads progress out of
the memory of the running machine, from the character array the game itself
maintains at \Mrecords{} records of \MrecordBytes{} bytes, and out of the save
file the game writes when asked, which is where the party and the world
position are true. The agent never sees any of this and has no call that
returns it. Screen-derived quantities are reported as behaviour, never as
progress, so no amount of visual churn can move a progress metric.

We make three contributions.

\begin{enumerate}
\item We present \bench{}, a long-horizon benchmark on an unmodified
commercial open-world role-playing game, whose difficulty comes from named
and independently checkable properties of the environment: out-of-distribution low-resolution perception, isometric control,
Traditional Chinese grounding, a keyboard action space of \MkeyNames{} names
over \MkeyCodes{} distinct keys of which a small subset does anything, and
persistent character state that only coherent play advances.

\item We score progress in the terms the game keeps. Character records, the party
and the fourteen books are read from emulator memory and from a save the game
performs for itself, validated against the archives the release ships and
against positive and negative controls, and measurement never writes to the
machine it observes. Every rung of the ladder is therefore an event that
screen similarity cannot manufacture, and the terminal rung is the ending the
game defines.

\item We evaluate \NmodelLabels{} agent configurations from \Nvendors{}
vendors and a seeded random baseline under a wall-clock budget, and report a
behavioural profile alongside the ladder in place of a single score. The
profile separates configurations that share a progression result, and resolves
how a session spends a budget it has not yet learned to use.
\end{enumerate}

The interface is deliberately thin. A participant pastes one line into an
agent, and the benchmark serves the brief, the key vocabulary and the session
address behind it; there is no SDK, no container and no framework to adopt.
Every run is recorded end to end and published with an interactive replay, so
a claim about a run can be checked against the run.

\section{Related Work}
\label{sec:related}

\subsection{Game Environments as Agent Benchmarks}

Games have been the standard setting for sequential decision-making since the
Arcade Learning Environment \citep{bellemare2013arcade}, and the arrival of
language and vision-language agents produced a second wave of them. BALROG
aggregates six reinforcement-learning environments under one protocol and
reports a persistent gap between what a model knows about a game and what it
does inside one \citep{paglieri2025balrog}. lmgame-Bench isolates how much of
a game result belongs to the harness rather than the model
\citep{hu2026lmgame}, and Orak spans twelve popular titles with configurable
agentic modules \citep{park2026orak}. VideoGameBench is closest to our
setting, running real 1990s games from raw pixels under a no-scaffold rule
\citep{zhang2025videogamebench}. GameWorld standardises the action interface
across 34 browser games and pairs every task with a state-verifiable metric
\citep{ouyang2026gameworld}. MineExplorer evaluates open-world exploration in
Minecraft and finds that models handle single-hop tasks but degrade sharply
once hidden prerequisites must be coordinated across a longer trajectory
\citep{ju2026mineexplorer}, which is the structure of the opening sequence in
our environment as well. Crafter established the single-environment,
achievement-based design we follow \citep{hafner2021benchmarking}, and
NetHack remains the depth extreme for learned agents
\citep{kuttler2020nethack}.

\bench{} differs along five axes. It runs one persistent open world where the
comparable benchmarks run suites of level-structured games. It treats
Traditional Chinese text as a core obstacle where they treat text as absent or
incidental. It verifies progress from emulator memory and from the save file
of the game where they verify from screen similarity. It scores against the
completion condition the game defines, which gives the ladder a terminal rung
and the leaderboard a second scale in completion time. And it is a public
wall-clock arena that any harness can enter.

\subsection{Long-Horizon Evaluation and Its Measurement}

Vending-Bench established long-term coherence as the property that separates
long-horizon tasks from long chains of short ones
\citep{backlund2025vending}, and E-Commerce Bench extends the continuing
formulation to a year of deterministic business operation
\citep{fan2026ecommerce}. Both keep perception out of the loop. TextQuests
shares our self-directed, long-horizon framing while removing vision
\citep{phan2025textquests}, and TextAtari stretches horizons to $10^5$ steps
over text renderings \citep{li2025textatari}. ARC-AGI-3 isolates fluid agency
by excluding language and culture \citep{arc2026arcagi3}, and AutumnBench
probes world-model quality through environment-level queries
\citep{warrier2025benchmarking}.

The measurement question is the one this paper takes seriously. The ABC
checklist catalogues task-validity and outcome-validity failures across
agentic benchmarks \citep{zhu2025establishing}, and the survey of the horizon
gap finds that the field answers uninformative outcome signals by building
denser step-level ones \citep{chen2026horizongap}. Our milestone ladder and
the behavioural profile beneath it are an instance of that answer, with the
ladder read from machine state so that the dense signals cannot be confused
with progress. For behavioural quantities we follow GVGAI-LLM in
distinguishing effective from redundant actions \citep{li2025gvgai}, and we
report a binomial proportion with its interval in place of a bare rank, in
the spirit of comparative platforms that account for ranking uncertainty
\citep{chiang2024chatbot,wilson1927probable}.

\section{\bench{}}
\label{sec:bench}

\subsection{Environment}
\label{sec:env}

\game{金庸群俠傳} (Heluo Studio, 1996) opens with the protagonist in a small
compound, and the fiction supplies the only standing instruction: enter the
world of the Jin Yong novels, join its factions, learn its martial arts, and
recover the fourteen books that end the game. The world is two-tier, with
many local scenes such as buildings, sects and caves attached to one large
outdoor map. The game maintains, for each of \Mrecords{} named characters, a
record carrying level, experience, health, stamina, learned skills, carried
items, reputation and aptitude. Progression is nonlinear and gated: most
buildings stay shut until specific items are held, and the opening sequence
must be completed before much of the map becomes reachable at all. The
opening compound is a single scene containing a searchable chest, furniture,
one speaking character, and exactly one exit tile.

it receives them. Every objective, choice and statistic in the game is stated

\Cref{fig:screens} shows what that state looks like from the outside. Every
objective, prompt and statistic reaches the agent as Traditional Chinese
rendered at sixteen pixels a line, and the character sheet it would have to
read is the same record the benchmark reads from memory.

We selected this title over better-known Western games for four reasons. Its
text is Traditional Chinese throughout, which makes cross-lingual grounding a
first-class obstacle. It is menu-driven, not
reflex-driven, so an agent that deliberates between actions is not
structurally disadvantaged in the way a real-time action title would
disadvantage it \citep[cf.][]{zhang2025videogamebench}. Its progression state is rich
enough to measure at the level of individual character statistics. And its
$45^\circ$ isometric projection makes the mapping from screen to action
something the agent must infer.

\subsection{Observation and Action Interface}
\label{sec:interface}

The agent observes the raw framebuffer at $320\times200$ and acts by pressing
keys. Frames are upscaled without interpolation when a larger image is
requested, so no information is added and none is smoothed away. Nothing is
annotated: there is no set-of-marks overlay and no accessibility tree
\citep[cf.][]{xie2024osworld}. The action space is the DOS keyboard,
\MkeyNames{} names over \MkeyCodes{} distinct keys, of which the game
responds to a small subset that the agent must discover. Movement runs along
the four numpad diagonals, with the arrow keys aliased onto the same four
axes, so an agent that presses \texttt{up} expecting to walk up the screen
moves up and to the right instead.

The control surface is nine calls, and one way to do each thing:

\begin{tabular}{@{}lll@{}}

Call & Body & Meaning \\
\midrule

\bottomrule
\end{tabular}

An action waits for the screen to react and then to hold still before it
returns, so the frame an agent receives is the consequence of the key it
sent. A key press is held for a fixed number of emulated frames, not
for wall-clock time, because the game samples its keyboard once per
game-loop iteration and a shorter pulse can be consumed without registering.
A scored session withholds the snapshot calls: a run with an out-of-band
rewind is not a run.

\subsection{Session Protocol}
\label{sec:protocol}

A participant joins by pasting one line into an agent:

\begin{lstlisting}
Read https://hanxiao.io/jy-crpg-bench/agents.md and play it.
\end{lstlisting}

\noindent The brief behind that address is the whole contract: how to open a
session, the calls that constitute play, the rules of a run, and orientation
advice equivalent to the first page of a game manual. It is served in English
and Simplified Chinese, with the on-screen Traditional terms of the game kept
verbatim in both, so the language an agent reasons in is not itself a
handicap.

A session is created with a playtime, twenty minutes by default, and the
clock starts at the first playable moment, not at connection. Each
session is a separate emulator process with a private copy of the game, so no
state, filesystem or snapshot is shared between sessions; twenty-four
sessions run concurrently on one eight-vCPU host. An agent that goes ten
minutes without pressing a key is torn down and recorded as idle, because
deliberating for ten minutes over one action is a failure mode under a
wall-clock budget, not a thinking style. When the budget lapses the
session renders its recording to video, computes its metrics, and appends
itself to the public catalogue. \Cref{fig:apparatus} shows the apparatus.

Because the protocol is plain HTTP, submitting to the benchmark and pointing
an agent at an address are the same act. We fix nothing about memory,
prompting or reasoning strategy, and report the model and harness that
actually played. Harness choice is known to move game results
\citep{hu2026lmgame}, and decomposing model capability from harness
capability is an open problem for the field \citep{chen2026horizongap}; we
therefore treat a submission as a system, not as a model, and keep the
full recording so that its behaviour is auditable.

\subsection{State-Verifiable Progress}
\label{sec:measure}

The save format of the game is a plain six-section archive whose second
section is \Mrecords{} records of \MrecordBytes{} bytes, one per named
character, with fields for level, experience, health, skills, items,
reputation and aptitude. We validated that layout against the save files the
game itself ships, where only \Moverflow{} of \Mrecords{} records violate
$\mathrm{hp}\le\mathrm{maxHp} \lor \mathrm{mp}\le\mathrm{maxMp}$, and then
located the same array in the live emulated machine by anchoring on a
character name that occurs exactly once and confirming two neighbouring
records at the correct stride. A read costs 1.2\,ms through serialisation
into a reused buffer, and a cached anchor check costs 0.3\,$\mu$s. The shared
inventory sits immediately in front of that array and moves the moment an item
is taken, which is how the item count and the books held are current rather
than last saved. Measurement is read-only: the benchmark may serialise the
machine but never loads state into it, so observing a run cannot alter it.

Two quantities are not live in memory. The party roster and the world
position exist there only as the copies the game loaded when the run began,
and they do not follow the player, so the benchmark asks the game to save. The
game offers its save menu on the world map alone and announces as much through
the height of that menu, so an attempt opens the menu, counts its rows and
withdraws where saving is not offered, returning the screen unchanged. The
archive it writes is read the same way as the shipped ones. Neither the save
nor anything read from it is reachable through the control surface, for the
same reason the snapshot calls are withheld from a scored session.

Scene changes are detected from the fade to black that the renderer performs
on every transition. We sample mean framebuffer luminance each frame while
waiting for the screen to settle. The opening scene reads 92, a transition
reads 0, and the threshold of 12 sits far from anything the game otherwise
draws. Both controls are exercised: 74 actions of walking and menu-toggling
produce no false positive, and a flood-fill of the opening scene that locates
its exit tile confirms the detector fires exactly at the transition. Every
detector carries a demonstrated positive control before its numbers are
reported anywhere.

Progress is summarised as seven ordered milestones read from this ground
truth, in the spirit of the achievements of Crafter
\citep{hafner2021benchmarking}: \emph{acted} $\prec$ \emph{picked something up}
$\prec$ \emph{reached the world map} $\prec$ \emph{gained experience} $\prec$
\emph{reached level~2} $\prec$ \emph{recruited a companion} $\prec$
\emph{holds one of the fourteen}. Only the first concerns the harness; the
rest are the numbers the game keeps about itself. Because each rung is harder
than the one before it, the count of rungs is an ordering and carries no
weights. A rung whose instrumentation post-dates a run is reported as
unmeasured and never as failed, since an unmeasured zero and a true zero are
different claims.

The ladder ends where the game does. Recovering all fourteen books is the
condition the fiction sets and the state the archive records, so the last rung
is not a proxy for finishing but finishing itself. Sessions run to
twenty-four hours on the same protocol, and a session that reaches the ending
carries a completion time, which is the quantity that orders a field where
every entrant passes. One instrument therefore covers both regimes, and the
benchmark keeps measuring after the first model finishes.

\subsection{Behavioural Metrics}
\label{sec:metrics}

Beneath the ladder we record what the agent did, computed from the traffic of
the run itself so that the quantities hold for any harness. The
\emph{meaningful-step ratio} is the share of actions that changed the screen
at all, and \emph{oscillation} is the share that reverse the previous one.
These follow the effective-versus-redundant distinction of GVGAI-LLM
\citep{li2025gvgai} with operational definitions of our own, since GVGAI-LLM
uses reward or symbolic state changes. We also record screen reads per
action, which says whether a model looks before it acts; think-time
percentiles taken from inter-action gaps; time to first action; and
action-space coverage as the count of distinct keys used.

The meaningful-step ratio is a binomial proportion, so we report 95\% Wilson
intervals \citep{wilson1927probable} and group configurations whose intervals
overlap in place of ranking them outright. Ratio alone rewards near-inaction,
since a single considered action scores 1.0, and count alone rewards pressing
keys as fast as the protocol allows, so we also report the
quality-throughput frontier and treat one configuration as dominating another
only when it is better on both.

\section{Experiments}
\label{sec:results}

\subsection{Setup}

The field is \NmodelLabels{} agent configurations drawn from \Nvendors{}
vendors, together with a seeded random-key baseline, over \Nsessions{} scored
sessions at the \Nbudget{}-second budget. Configurations are self-declared by the agent
that connects, and a submission is a completed run. Every session in this
paper is public, with its video, replay timeline and metric record reachable
from the leaderboard. The random baseline draws from the same key vocabulary
the brief teaches, at a cadence in the range agents achieve, and never reads
the screen.

The field therefore stands at the early rungs of a ladder whose last one is
the ending of the game, which is where comparable instruments place it as
well: BALROG reports its best model at $1.5\%$ progression on NetHack
\citep{paglieri2025balrog} and VideoGameBench reports the best
vision-language models completing $0.48\%$ of its suite
\citep{zhang2025videogamebench}. What an instrument owes the field at this
stage is resolution underneath the rung it has reached, and the rest of this
section supplies it.

\subsection{Behavioural Profiles}

\begin{figure}[t]
\centering
\includegraphics[width=0.62\linewidth]{figures/pareto.pdf}
\caption{Quality against throughput, with 95\% Wilson intervals on the ratio.
Neither axis alone is a score: the ratio rewards near-inaction and the count
rewards speed alone. The dashed line joins the runs dominated on neither
axis.}
\label{fig:pareto}
\end{figure}

Configurations that share an identical progression result behave very
differently, and \cref{tab:results} separates four styles. The most deliberate
configurations, Claude Sonnet 5 and Qwen3.8, hold high meaningful ratios at the
lowest throughput, near 50 actions in twenty minutes: almost every action is considered and lands, but at a median think
time of 21\,s the budget expires before the plan does. Claude Fable 5 takes
\QsteadyN{} actions at a ratio of \Qsteady{} and an oscillation rate of
\QsteadyOsc{}, which is the closest behaviour to purposeful traversal the
field produces.
The random baseline never reads the screen, acts every 1.4\,s, and still
changes the screen \Qrandom{} of the time, which measures the reactivity of
the environment, and sets the floor any model should clear. \Cref{fig:pareto} shows that neither quality nor throughput
orders the field on its own.

One configuration falls below that floor. Gemini 3.7 Flash reads the screen
before 99\% of its \QworstN{} actions, acts quickly, and reaches a meaningful
ratio of \Qworst{}, roughly six times below random. Its replay shows
minutes-long repetition of keys the game ignores in the mode it is in;
oscillation is low because the screen almost never changes at all, and it
spends \QworstStart{} minutes before its first keypress. Reading the screen
frequently therefore does not establish that a model perceives it, a
divergence between looking and seeing that BALROG and VideoGameBench also
document \citep{paglieri2025balrog,zhang2025videogamebench}.
\Cref{fig:behaviour} separates the three quantities that produce these
styles: how often a session looks, how long it thinks, and how much it does.

\subsection{Use of the Budget}

\begin{figure}[t]
\centering
\includegraphics[width=0.95\linewidth]{figures/horizon.pdf}
\caption{One row per scored session. Grey is time inside the opening scene,
accent is time on the world map, with the action count at which the

\label{fig:horizon}
\end{figure}

\Cref{fig:horizon} accounts for the twenty minutes directly. Most sessions
spend the entire budget in the scene they spawned in. The sessions that do
leave it cross at a median of \SexitActs{} actions and \SexitMedian{} minutes,
which means that reaching the second scene consumes roughly half the budget
for the configurations that reach it at all. Two vendors account for every
corroborated crossing.

This distribution explains why the twenty-minute budget measures early
competence, and why we price deliberation in wall clock: a configuration
thinking 20\,s per action spends a third of the run deciding, an efficiency framing shared with
\citet{arc2026arcagi3} and \citet{phan2025textquests}. The protocol supports
budgets to twenty-four hours, which is the setting in which the later rungs
and a completion time come within reach.

\tbd{Runs at longer budgets, which the protocol already supports, are the
measurement that would separate a slow agent from a stuck one.}

\subsection{The Random Baseline}

The seeded random policy is load-bearing, following
\citet{hafner2021benchmarking} and the validation methodology of
\citet{arc2026arcagi3}. It defines the reactivity floor for every behavioural
metric, at \Qrandom{} meaningful, \QrandomKeys{} distinct keys and no screen
reads. It is the control against which a new metric is audited before it is
reported. And it bounds the difficulty claim: across \QrandomN{} random actions the
exit tile is never reached.

\section{Conclusion}
\label{sec:conclusion}

We presented \bench{}, a long-horizon benchmark that runs an unmodified 1996
open-world role-playing game and scores agents in the terms the game keeps
about itself. The environment is adversarial in ways that are named and
checkable: a $320\times200$ isometric frame far outside the training
distribution of current vision encoders, Traditional Chinese as the only
channel through which objectives are stated, and a world that supplies no
score. Progress read from the memory of the environment and from a save the
game performs for itself cannot be manufactured by visual churn, and every
rung of the ladder is an event the agent has to cause.

The ladder ends at the ending of the game. Recovering the fourteen books is a
state the archive records, so a model that finishes leaves proof of it, and
the benchmark then ranks by the time it took. We built both scales at once so
that the first finishing model changes what the leaderboard measures, and so
that the run which gets there is on record and replayable frame by frame.

\section*{Ethics statement}
The benchmark evaluates publicly released models on a commercial game under
emulation, and involves no human subjects. Recordings contain only game
frames and the agent name a model chooses for itself. The benchmark runs an
unmodified, long-out-of-print commercial title and distributes no game
assets; participants supply their own copy, as in prior work benchmarking
commercial games \citep{zhang2025videogamebench,bellemare2013arcade}, and the
rights holders retain all rights. Improvements in open-world agency transfer
to autonomous operation in the world, and we believe public, legible
measurement of these capabilities supports oversight.

\section*{Reproducibility statement}
Every run in this paper is public, and each carries a stable address with its
video, interactive replay timeline and metric record, linked from the
leaderboard at \url{https://hanxiao.io/jy-crpg-bench/}. The brief served to
agents, the interface of \cref{sec:interface}, the metric definitions of
\cref{sec:measure,sec:metrics}, the detector calibrations and their controls,
and the seeded random baseline together specify the evaluation.

The stack is open source at \url{https://github.com/hanxiao/jy-crpg-bench}.
Every number typeset in this paper is generated, never typed: the frozen
inputs are \texttt{figures/catalog\_snapshot.json} and
\texttt{figures/start.state}, the savestate every session boots into and the
state panel (a) of \cref{fig:opening} shows. Generator scripts turn those into the
macros used throughout, and a consistency check fails the build if a latched
claim or floor drifts from the snapshot. Re-executing the game needs a
self-supplied copy of the 1996 release, described in
\cref{app:licence}; re-deriving every reported number does not.

\section{The Agent-Facing Brief}
\label{app:brief}
The complete onboarding surface is the brief served at \texttt{agents.md}:
session creation, the calls that constitute play, the rules of a run covering
budget, idle teardown, recording and publication, the isometric key mapping
with an explicit warning that arrow-key intuitions do not hold, early

cannot drift from the behaviour. The English and Simplified Chinese versions
are equivalent in rules, with on-screen Traditional terms preserved in both.

\section{Metric Definitions}
\label{app:metrics}
For a run with actions $a_1,\dots,a_n$ at wall-clock times $t_1,\dots,t_n$,
playable-from time $t_0$, and post-settle screen fingerprints
$f_1,\dots,f_n$: the meaningful-step ratio is
$\frac{1}{n}\sum_i \mathbf{1}[f_i \neq f_{i-1}]$; the oscillation rate is
$\frac{1}{n}\sum_i \mathbf{1}[f_i = f_{i-2} \wedge f_i \neq f_{i-1}]$; time to
first action is $t_1 - t_0$; think-time percentiles are taken over
$\{t_i - t_{i-1}\}$; reads per action is the count of screen reads over $n$;
and action-space coverage is the number of distinct keys used. Fingerprints
are $12\times8$ three-bit-quantised grayscale downsamples with the
camera-locked sprite region masked, and they are used for behaviour only.
Milestones read machine state as described in \cref{sec:measure}. Wilson
intervals use $z=1.96$ \citep{wilson1927probable}, and a displayed rank range
spans the positions consistent with pairwise interval overlap, which is a
display convention rather than the preference-based ranking procedure of
\citet{chiang2024chatbot}.

\section{Session and Infrastructure Parameters}
\label{app:infra}
The default budget is \Nbudget{}\,s and is configurable to 24\,h; idle
teardown is 600\,s; the concurrency cap is 24 sessions per 8-vCPU, 8\,GiB
host, measured at 32 sessions holding native 70.09\,fps with memory rather
than CPU binding first, at about 123\,MB of game copy per run. Emulation is
DOSBox Pure through libretro at authentic cycle settings, with per-session
private copies of the game and save directories. Recordings are stored as
$16\times10$-tile zlib deltas; published video is native $320\times200$ with a
timeline sidecar of 7--13\,KB carrying every keypress and its hold duration
for the scrubbable replay. A character-state read costs 1.2\,ms and is
sampled every fifth action; a luminance sample costs 1.1\,$\mu$s per frame
while the screen settles. The leaderboard is a static page polling published
JSON, so spectators place no load on game hosts.
